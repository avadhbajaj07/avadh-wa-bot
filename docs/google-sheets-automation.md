# Google Sheets automation setup

1. Apply `supabase/migrations/043_google_sheets_automation.sql` before deploying the app. The new tables have RLS enabled and no browser access policies; server routes use the Supabase service role.
2. In Google Cloud, enable the Google Sheets API, Google Drive API, and Google Picker API. Configure an OAuth Web application with the authorized redirect URI `https://YOUR_DOMAIN/api/google/callback`. Request the `spreadsheets` and `drive.file` scopes. Complete Google's consent screen requirements before inviting client accounts.
3. Set `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `NEXT_PUBLIC_APP_URL`, `NEXT_PUBLIC_GOOGLE_PICKER_API_KEY`, and `NEXT_PUBLIC_GOOGLE_PROJECT_NUMBER`. `ENCRYPTION_KEY` must be a stable, private 64-character hex key. Keep the Google client secret, Supabase service role key, and encryption key server-side.
4. Open **Settings → Google Sheets** as an account admin. Connect Google. The app creates a client-named Drive folder and the Leads, Bulk WhatsApp Campaign, and Failed Messages spreadsheets. Select an approved WhatsApp template for Leads or Bulk. A sheet with no template does not send.
5. For each sending sheet, click **Get Apps Script setup**, paste it into that spreadsheet's **Extensions → Apps Script**, save, and run `setupSheetAutomation` once. Grant the requested permissions. The installable edit and form submit triggers send new or changed rows in batches of up to 200. A row is sent only once; editing an already sent row does not resend it. The bound script contains a private webhook key, so restrict spreadsheet editor access.
6. To connect a spreadsheet that already exists, click **Connect existing sheet** in settings and pick a Google spreadsheet. The selected tab must have `Name` and `Phone` headings in row 1. The first tab is used by default. Install its generated Apps Script in that spreadsheet too.
7. For an order source with a direct webhook, use **Show endpoint and secret** in settings. Configure the store to POST JSON with `order_id`, `name`, `phone`, and `details` and an `x-store-secret` header. The active Bulk template is sent before the order is appended to the Bulk sheet. Repeated `order_id` values are deduplicated by Supabase.

Supabase holds connection, sheet, message, and order state. Sheet write failures do not cause a second WhatsApp send. Google refresh tokens and sheet/store webhook secrets are AES-256-GCM encrypted with `ENCRYPTION_KEY`; plaintext secrets are never stored in Supabase. Rows without a valid phone or required template values are skipped. No production Google or Meta credentials are included in the repository.
